# Perencanaan Penulisan SRS - 2.1 Product Perspective

*Referensi Panduan IEEE 830-1998:*
> Bagian Perspektif Produk (Product Perspective) menempatkan perangkat lunak dalam sebuah konteks dengan sistem lain. Penulis harus menjelaskan apakah produk ini merupakan sistem yang sepenuhnya mandiri (*independent*) atau merupakan komponen dari sistem yang lebih besar. Bagian ini umumnya menguraikan blok diagram sistem, antarmuka sistem (hardware, software, user, communication), dan arsitektur dasarnya.

---

### **Rencana Isi (Plan) untuk ATLAS - 2.1 Product Perspective:**

Pada draf asli nanti, bagian ini akan dijabarkan menjadi narasi yang memuat elemen-elemen berikut:

**1. Konteks dan Kedudukan Sistem (System Context)**
- **Rencana:** Menegaskan bahwa ATLAS adalah ekosistem yang menggabungkan perangkat keras tertanam (*embedded system*) berbasis ESP32 di kereta dengan platform Website untuk *monitoring*.
- **Penjelasan:** ATLAS tidak mengambil alih sistem kendali bawaan pabrik kereta, melainkan berfungsi sebagai *Secondary Safety System* (sistem pengaman lapis kedua).

**2. Arsitektur Terdesentralisasi (Decentralized P2P Topology)**
- **Rencana:** Mendeskripsikan diagram konseptual komunikasi sistem operasional *on-board*.
- **Penjelasan:** Modul ESP32 di setiap kereta saling menyiarkan dan mendengarkan data menggunakan LoRa P2P. Tidak memerlukan sinyal internet komersial untuk fungsi pengereman daruratnya.

**3. Antarmuka Komunikasi (Communications Interfaces)**
- **Rencana:** Menguraikan jalur komunikasi sistem.
- **Penjelasan:** Komunikasi RF (LoRa) untuk pertukaran parameter antar kereta, serta komunikasi TCP/IP (Wi-Fi/GSM dari ESP32 Gateway) untuk mengirimkan data pemantauan ke *Web Server*.

**4. Antarmuka Perangkat Keras Utama (Hardware Interfaces)**
- **Rencana:** Menggambarkan komponen keras esensial pada purwarupa.
- **Penjelasan:** Sistem ESP32 terhubung dengan modul GPS RTK (sebagai sensor input), modul lampu LED dan Buzzer (sebagai *output* peringatan lokal), serta modul relay mekanik (sebagai aktuator pengereman).

**5. Antarmuka Pengguna (User Interfaces)**
- **Rencana:** Memberikan gambaran UI di kabin lokomotif dan UI pada Website.
- **Penjelasan:** UI kabin sangat minimalis (hanya LED merah/kuning dan bunyi alarm Buzzer). UI Website berbasis *dashboard graphical* interaktif bagi *dispatcher* untuk melihat peta jalur dan analitik data telemetri historis.
